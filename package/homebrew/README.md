# Homebrew tap staging

This directory is the staged, in-repo mirror of the planned dedicated Homebrew
tap repository `assistant-ui/homebrew-riftri`. Its layout matches what Homebrew
expects at a tap's root, so publishing the tap is a copy, not a rewrite:

- `Formula/riftri.rb` — the formula, byte-identical to the repository-root
  [`Formula/riftri.rb`](../../Formula/riftri.rb). Both are generated by
  [`package/scripts/update-homebrew-formula.mjs`](../scripts/update-homebrew-formula.mjs);
  never edit either by hand.
- `README.md` — this file. Replace the staging notes with the tap repository's
  own installation instructions when publishing.

Until the tap repository exists, the supported Homebrew installation remains
`brew install --formula ./Formula/riftri.rb` from a repository checkout, as
documented in [docs/install.md](../../docs/install.md). Once a maintainer
creates the tap, installation becomes:

```sh
brew tap assistant-ui/riftri
brew install assistant-ui/riftri/riftri
```

## Keeping the formula in sync

After every release, regenerate both formula copies from that release's
published `SHA256SUMS`:

```sh
node package/scripts/sync-homebrew-tap.mjs           # latest release
node package/scripts/sync-homebrew-tap.mjs v0.2.3    # specific tag
node package/scripts/sync-homebrew-tap.mjs --check   # verify only, no writes
```

The script downloads the manifest from the release itself, so the pinned
checksums are by construction the published ones. Three guards keep the copies
honest:

- `package/test/homebrew-formula.test.js` fails in CI when either copy stops
  matching the generator's output or when the two copies differ.
- `.github/workflows/homebrew-freshness.yml` fails daily when the formula
  falls behind the latest release or pins a checksum the release does not
  publish.
- The formula's `test do` block asserts the installed executable reports the
  formula version and that `riftri doctor --json` produces a capability
  report.

## Publishing the tap (maintainer access required)

Creating the tap repository and pushing to it are deliberate maintainer
actions; nothing in this repository automates them.

1. Create a public `assistant-ui/homebrew-riftri` repository. The `homebrew-`
   prefix is what lets `brew tap assistant-ui/riftri` resolve it.
2. Run the sync check here, then copy this directory's contents
   (`Formula/riftri.rb` and a tap-facing `README.md`) to the tap repository's
   root and push.
3. Verify on a machine without a Riftri checkout:

   ```sh
   brew tap assistant-ui/riftri
   brew install assistant-ui/riftri/riftri
   riftri --version
   brew test assistant-ui/riftri/riftri
   ```

4. After each subsequent release, repeat the sync and copy. Keep the tap's
   formula identical to the staged copy so this repository's guards vouch for
   what the tap serves.

Only update [docs/install.md](../../docs/install.md) to advertise the tap
command after step 3 has actually been verified.
